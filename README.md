# NVIDIA PTX ISA v9.4 — Markdown Reference + MCP Server

Community-maintained, hand-converted Markdown edition of the [NVIDIA Parallel Thread Execution ISA v9.4](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html), served as a documentation site, a REST API and an MCP server so that coding agents can read the spec section by section.

**Hosted at [ptx.poole.ai](https://ptx.poole.ai)** — MCP endpoint at `/mcp`, REST API at `/api`.

> **Disclaimer:** This is an unofficial reformatting for readability and tooling integration.
> The authoritative source is always [NVIDIA's official documentation](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html).

---

## What is covered

Every chapter of the 9.4 specification, as one Markdown page per instruction, directive, special register or concept section (about 420 pages):

| Chapter | Where |
|---|---|
| 1–4 Introduction, programming model, machine model, syntax | [`mcp-server/docs/01-…04-*.md`](mcp-server/docs/) |
| 5 State spaces, types, variables, tensors (incl. swizzling and tensor-maps) | [`05-state-spaces-types-variables/`](mcp-server/docs/05-state-spaces-types-variables/) |
| 6–8 Operands, ABI, memory consistency model | [`06-*.md`, `07-*.md`, `08-memory-consistency-model/`](mcp-server/docs/) |
| 9 Instruction set — integer, floating point (incl. the new alternate-FP packed instructions), comparison, logic, data movement & conversion (`ld`/`st`/`cvt`/`cp.async*`/`tensormap.*`/`spcompress`), **fabric** instructions, texture, surface, control flow, synchronisation (`atom`/`red`/`fence`/`mbarrier.*`/`clusterlaunchcontrol.*`), warp-level `mma`/`wmma`/`ldmatrix`, `wgmma`, **tcgen05**, stack, video, misc | [`09-instruction-set/`](mcp-server/docs/09-instruction-set/) |
| 10 Special registers | [`10-special-registers/`](mcp-server/docs/10-special-registers/) |
| 11 Directives | [`11-directives/`](mcp-server/docs/11-directives/) |
| 12 `.pragma` strings | [`12-pragma-strings/`](mcp-server/docs/12-pragma-strings/) |
| 13 Release notes (per-version change lists and the target/feature history tables) | [`13-release-notes/`](mcp-server/docs/13-release-notes/) |
| 14 Notices | [`14-notices.md`](mcp-server/docs/14-notices.md) |

Conventions: every page starts with its official section number, tables are reproduced row for row (merged cells written out explicitly), figures link to NVIDIA's images, and cross references are relative Markdown links. The pages are written by hand from the specification text, not generated by a script.

## Use the hosted MCP server

Claude Desktop / any HTTP MCP client (`~/.claude/claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "ptx-isa": {
      "type": "http",
      "url": "https://ptx.poole.ai/mcp"
    }
  }
}
```

Claude Code:

```bash
claude mcp add --transport http ptx-isa https://ptx.poole.ai/mcp
```

stdio-only clients via `mcp-remote`:

```json
{
  "mcpServers": {
    "ptx-isa": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://ptx.poole.ai/mcp"]
    }
  }
}
```

### MCP tools

| Tool | What it does |
|---|---|
| `search_ptx_isa` | Section-level BM25 full-text search with PTX-aware tokenisation (`cp.async.bulk.tensor`, `.shared::cluster`, `scale_vec::4X`, section numbers). Returns ranked hits with the page slug, the heading to pass to `read_ptx_isa_page`, and a snippet with the matched terms marked `«like this»`. The whole reply stays under `max_bytes` (default 4 KiB). Optional `scope` restricts to a slug prefix. |
| `read_ptx_isa_page` | Returns a page's Markdown, or just one `section` of it (by number such as `9.7.18.10.7.1`, or by heading such as `Syntax` / `Examples`). `slug` accepts a slug, an instruction/directive/register name (`tcgen05.mma`, `.maxntid`, `%laneid`), a file name, or a section number; ambiguous names return the candidate list. |
| `lookup_ptx_instruction` | Resolves a mnemonic (or a family prefix such as `mbarrier` or `cp.async.bulk`) to its page(s) without a full-text search. |
| `list_ptx_isa_pages` | Chapter/directory outline, or every page under a `prefix`, or pages whose title/slug/name matches `filter`. |

The legacy tool names `search`, `read_page`, `list_pages`, `ptx_search`, `ptx_read`, `ptx_list` still work. Pages are also exposed as MCP resources at `ptx://docs/<slug>`.

### REST API

```
GET /api/search?q=<query>&max=<n>&scope=<slug-prefix>
GET /api/read?slug=<slug-or-name>&section=<heading>
GET /api/lookup?name=<mnemonic>
GET /api/list?prefix=<dir>&filter=<text>
GET /raw/<slug>                       # raw Markdown
GET /docs/<slug>                      # rendered page
```

## Self-hosting

The [`mcp-server/`](mcp-server/) directory is a single Bun server ([`server.ts`](mcp-server/server.ts)) that serves the documentation browser, the REST API and the MCP endpoint (stdio and streamable HTTP) from the Markdown in [`mcp-server/docs/`](mcp-server/docs/). Search and page indexing live in [`mcp-server/lib/`](mcp-server/lib/).

**Prerequisites:** [Bun](https://bun.sh) ≥ 1.0

```bash
cd mcp-server
bun install
bun run start          # http://localhost:3000 ; stdio MCP when stdin is piped
bun run start --http   # HTTP only (also implied when $PORT is set)
```

Local MCP config over stdio:

```json
{
  "mcpServers": {
    "ptx-isa": {
      "command": "bun",
      "args": ["run", "/path/to/markdown-ptx-isa/mcp-server/server.ts"]
    }
  }
}
```

## Repository layout

```
mcp-server/
  server.ts        HTTP + stdio server, web UI, MCP dispatcher
  lib/docs.ts      page index: section parsing, name resolution, section extraction
  lib/search.ts    BM25F index, PTX tokenizer, hotspot snippets, byte-budgeted rendering
  lib/tools.ts     MCP tool definitions and implementations
  docs/            the Markdown reference (one page per instruction / section)
raw.txt            text dump of the official 9.4 specification the pages were written from
```
